# ShortVideo — Application Flows

**Version:** 1.0

## 1. Guest Flow

1. Open `/`.
2. View public discovery content according to access policy.
3. Search public profiles and videos.
4. When attempting a protected action, navigate to `/login`.
5. After successful authentication, return to the intended destination if safe.

Never accept an arbitrary external redirect from an untrusted query parameter.

## 2. Registration and Login

### Email/password

1. User opens `/signup`.
2. Enters email and password.
3. Supabase Auth validates the request.
4. If email confirmation is enabled, display the confirmation instructions.
5. On a valid session, load the profile and role information.
6. Route the user to `/` or the safe requested destination.

### Google OAuth

1. User chooses Google login.
2. Supabase starts the configured OAuth flow.
3. Google redirects to the configured callback.
4. Supabase validates the response.
5. The frontend restores the session.
6. Create or retrieve the associated profile using a trusted mechanism.

If OAuth configuration is missing, display a configuration error rather than simulating success.

## 3. Feed and Video Playback

1. Open `/`.
2. Request a paginated list of eligible published videos.
3. Apply visibility and moderation rules.
4. Load video metadata and permitted playback URLs.
5. Render a mobile-first video feed.
6. Load additional items as the user scrolls.
7. Pause off-screen videos and release unnecessary resources.
8. Display an error/retry state when playback fails.

## 4. Upload Flow

1. Open `/upload`.
2. Require authentication.
3. Select a video and enter its title, description, and optional thumbnail.
4. Validate supported format, size, and duration.
5. Create a video metadata record in a non-published state if required by the upload workflow.
6. Upload to the private `videos` bucket using an authorized path.
7. Verify upload completion and metadata.
8. Mark the video as `published` only after all required checks pass.
9. Display the new video on the owner's profile and eligible feeds.

The default moderation mode is instant publication after validation. Reported content can subsequently be restricted or removed by authorized staff.

If upload or metadata creation fails, do not leave a published record pointing to a missing object.

## 5. Like, Comment, and Follow

### Like
1. User presses Like.
2. UI updates optimistically if safe.
3. Database enforces uniqueness for `(user_id, video_id)`.
4. Roll back the optimistic state if the request fails.

### Comment
1. Validate comment length and content.
2. Insert a comment for an eligible video.
3. Enforce ownership for deletion.
4. Provide reporting and moderation support.

### Follow
1. User selects Follow.
2. Prevent following oneself if this is the chosen product rule.
3. Enforce uniqueness for `(follower_id, following_id)`.
4. Update the visible state only after success or safely roll back.

## 6. Private Messaging

1. User opens `/inbox`.
2. Fetch only conversations in which the authenticated user is a participant.
3. User opens `/messages/:conversationId`.
4. Backend verifies conversation membership.
5. Load paginated message history.
6. Subscribe to permitted realtime message events.
7. Verify the sender identity from the authenticated session, not a trusted client-supplied user ID.
8. Provide report/block actions.
9. Unsubscribe from realtime events when leaving the conversation.

A user must not be able to subscribe to or query another user's private conversations by changing a URL.

## 7. Notifications

1. An eligible event occurs, such as a follow, comment, or message.
2. A trusted process creates a notification.
3. Recipient can read their own notifications.
4. Recipient can mark their own notifications as read.
5. Notification content must not expose private information to unrelated users.

Do not let users generate arbitrary notifications for other accounts by directly inserting rows.

## 8. Live Streaming

1. User opens `/live`.
2. Application lists eligible live sessions.
3. User opens `/live/:liveStreamId`.
4. Server verifies visibility and any access restrictions.
5. The frontend requests authorized playback information from the configured live provider.
6. If no provider is configured, show a clear unavailable/setup-required message.
7. When a stream ends, update the session state through a trusted process or verified webhook.

Database status alone does not establish that a real broadcast exists.

## 9. Reporting and Moderation

1. User reports a video, comment, or profile.
2. Server validates the target and creates a report.
3. Report appears in `/admin/reports` for authorized staff.
4. Staff reviews evidence and applies permitted action.
5. Moderation status changes are recorded in an audit log.
6. The affected content becomes hidden, restricted, or removed according to policy.
7. Users receive appropriate notifications where applicable.

Users cannot resolve reports, alter moderation decisions, or write administrative audit entries.

## 10. Administration

### Staff
- View permitted moderation queues.
- Review reports.
- Apply authorized content moderation actions.
- Cannot assign privileged roles or alter protected platform settings unless explicitly authorized.

### Super Admin
- Manage staff roles through trusted server-side operations.
- Access permitted administrative dashboards.
- Manage platform settings.
- Review audit events.

All privileged actions must be verified server-side.

## 11. Advertising

1. Feed or video page reserves an ad placement.
2. If a compliant ad provider is configured, load its approved integration.
3. If no provider is configured or consent is missing, do not invent an ad or fake an impression.
4. Advertising failures must not prevent normal video playback.

Creator earnings and withdrawals are deferred beyond v1.

## 12. Failure States

Provide explicit states for:
- No network connection.
- Expired session.
- Invalid or oversized upload.
- Upload interrupted.
- Unauthorized conversation or admin route.
- Removed video.
- Failed playback.
- Missing OAuth configuration.
- Missing live-stream provider.
- Missing ad provider.
- Rate limit exceeded.

Never show fake success for failed server operations.
